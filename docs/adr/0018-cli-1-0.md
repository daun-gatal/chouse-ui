# 0018 — CLI 1.0: One Tool for People and Scripts

- **Status:** Accepted
- **Date:** 2026-10-04
- **Amends:** [0012](0012-chouse-cli.md) §3 (the machine-only output contract and the command list). Everything else in 0012 stands: PAT-only auth through `verifyBearer()`, the safety model (`--yes`, `--dry-run`, fail closed without a terminal), the exit codes, the privilege fence and the independent `cli-vX` release line.
- **Builds on:** [0011](0011-personal-access-tokens.md) (PATs), [0017](0017-mcp-managed-in-the-ui.md) (MCP commands)

## Context

ADR 0012 shipped the CLI as a machine surface: JSON or YAML only, `table`
and `csv` removed. Using it in production showed that the CLI is used by
people at least as much as by scripts, and that several things were not
production-grade:

1. **Hostile to people.** Every command printed the raw API payload as
   indented JSON, also in a terminal. Query results could not be read, and
   lists of jobs or sessions were pages of fields.
2. **Secrets on the command line.** `auth login --token ch_pat_…` was the
   only documented way to log in, which puts the token in shell history
   and the process list.
3. **Stubs and fakes.** `config use-profile`, `table create|drop`,
   `connection create|delete` and `upload into` only printed "use the UI";
   the four `logs` views sent the same request; `-c` only took UUIDs.
4. **Promises not kept.** 0012 specified `--debug` (none existed) and
   `Retry-After` backoff (none existed); unknown subcommands of a group
   printed help and exited 0, so a typo looked like success.
5. **Hard to test and to interrupt.** Commands called `os.Exit` from deep
   inside handlers, so deferred cleanup never ran and nothing could be
   tested in-process; Ctrl-C did not cancel the request in flight; two code
   paths built HTTP clients outside the shared builder (one skipped TLS
   settings).

## Decision

1. **Auto output.** `-o auto` (the default) prints a **table** when stdout
   is a terminal and **JSON** when it is piped, like `gh` and `kubectl`.
   `table`, `csv`, `json` and `yaml` can be picked explicitly. Tables and
   CSV show curated columns per command (falling back to a list's scalar
   fields); JSON and YAML always print the full server result, unchanged.
   Query results keep ClickHouse's column order; `--out FILE` writes them
   with the format taken from the extension. Notes go to stderr.
2. **Tokens never as arguments.** `auth login` reads the token from a
   hidden prompt, `--token-stdin` or `CH_HOUSE_PAT`; `--token` still works
   but warns. `--insecure-skip-tls-verify` is never stored; `--ca-cert` is.
3. **Real profiles.** `config view|get|set|unset|use-profile|profiles|delete-profile`
   manage `server`, `connection`, `output` and `ca_cert`. Tokens are not a
   config key.
4. **Connections by name.** `-c` takes a connection name or id; names are
   resolved against the connections the token can use, with the choices
   listed when a name does not match.
5. **Every command returns an error.** One place maps errors to the exit
   codes (adding `130` for an interrupt), prints the server's request id
   and a hint. The context is cancelled on Ctrl-C/SIGTERM and bounded by
   `--timeout`. All I/O goes through injectable streams, so commands are
   tested in-process against a fake server.
6. **Operational flags kept honest.** `--debug` traces each request
   (method, path, status, time, request id — never headers or the token);
   GETs retry on network errors, 429 and 502/503/504 honoring
   `Retry-After`; writes are never retried. An unknown subcommand is a
   usage error. `chouse status` reports whether the server version is
   supported (3.14.0+).
7. **No stub commands.** Commands that only pointed at the UI or repeated
   another are removed; the UI-only list lives in the docs, not in the
   command tree.

This is a breaking release of the CLI line (1.0.0).

## Consequences

- Interactive use is readable without `jq`; scripts that pipe keep JSON
  without any change. Scripts that relied on JSON in a terminal set
  `CHOUSE_OUTPUT=json`.
- Tables are a presentation, not a contract: scripts must use JSON/YAML.
- A small new dependency (`golang.org/x/term`) for the hidden prompt.
- The e2e suite checks the new behaviours (login from stdin, names for
  `-c`, formats, `--debug` without the token, unknown subcommands).

## Alternatives considered

- **Keep JSON-only and add `--pretty`.** Leaves the default hostile in the
  place people use it most (a terminal), for no benefit to scripts, which
  are not terminals.
- **Typed models for every response.** A stable machine schema would need
  the server to version its API; until then JSON mirrors the server and the
  tables are curated per command.
- **OS keychain for tokens.** Better at rest, but platform-specific; the
  0600 credentials file plus env/stdin keeps CI and containers simple. A
  keychain backend can be added behind the same interface later.
