### Added
- **Where AI requests come from** — AI Governance › AI activity records who started each request: the UI, an MCP agent, a token caller such as the `chouse` CLI, or CHouse in the background, with the agent's name and the token it used (migration 1.60.0). The request list filters by origin and searches by client and token name, the tab splits tokens and cost by origin, and `GET /api/ai-usage/requests` takes `origin`. Requests recorded before this show *Not recorded*
- **MCP tools for what shipped since 3.14** — seventeen read-only tools, on by default and listed only for tokens with the matching permission: `get_ai_usage`, `get_ai_data_egress`, `list_ai_requests`, `get_ai_request` and `list_ai_agents` (the agent registry without prompts or skill files); `get_query_regressions`, `get_query_shape_history`, `get_capacity`, `list_upgrade_assessments`, `get_upgrade_assessment`, `get_canary_replay` and `get_upgrade_rollout`; `get_collector_status` and `get_collector_schedule`; `list_remediation_actions`, `get_remediation_action` and `get_investigation_notebook`. Two new catalog categories in AI Governance › MCP: *Performance, capacity & upgrades* and *AI governance*
- **CHouse Admin answers more** — the chat's *Operations Analyst* now covers query regressions, capacity, upgrade readiness and rollout, collector status and schedule, remediation actions and investigation notebooks; the *Platform Auditor* covers CHouse's AI agents, AI usage, estimated cost and data sent to providers. Built-in agents pick up the tools on start; customized ones show *Update available*
- **Notebook lookup** — `GET /api/notebooks/attached/:kind/:ref` returns the notebook of an incident or Doctor report without creating one, with the same permission checks as opening it
