type: patch

### Fixed
- **A scoped personal access token is held to its scopes everywhere** — a token whose scopes were narrowed could still pass permission checks on routes outside them when its owner held the permission. Every permission check for a token's request now answers from the token's own scopes. **If you rely on a scoped token for something outside its scopes, it now gets 403: add the permission to the token's scopes, or create a new token.** Tokens without scopes and browser sessions are unchanged.
- **An administrator's scoped token is held to its scopes in the SQL editor routes** — a statement from an administrator skips the permission check for its kind, and that applied to a scoped token too. A scoped token is now checked like anyone else's for the kind of statement (select, insert, DDL) and for the system tables that need a permission. Data access rules still do not restrict an administrator's token.
- **A scoped token does not act as an administrator** — an admin's or super admin's token kept the role whatever its scopes, so features that let an administrator act without a permission did not hold it to them. A scoped token no longer carries the admin or super admin role: it cannot see other people's dashboards or scheduled queries, approve high-risk actions, assign the super admin role, or change a connection's kind, role map or linked ClickHouse users. Use a browser session or a token without scopes for those. It still reaches the same connections as its owner.
- **The profile shows a token's own permissions** — `whoami` over MCP and `chouse auth whoami` listed the owner's permissions for a scoped token. They now list what the token may do.
- **Account names in the GRANT script** for linked ClickHouse users are written as plain comment text.
- **Connection details in the profile** — for someone who is not a super admin the profile no longer includes a connection's role names, server version or the reason a check failed, as on the connection list.
- **Linking a chat account needs a browser session** — creating a Telegram link code and unlinking a chat account are refused for a personal access token, like other actions that decide who can act as you.
